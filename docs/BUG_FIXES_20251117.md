# Bug Fixes Applied

## Issue 1: PlaceCard.jsx - `place.votes?.includes is not a function`

**Problem**: Old groups in Firestore have `votes` as an object `{}` instead of array `[]`

**Fix**: Added defensive code to handle both formats
```jsx
// Before:
const hasVoted = place.votes?.includes(currentUserId);

// After:
const votes = Array.isArray(place.votes) ? place.votes : [];
const hasVoted = votes.includes(currentUserId);
```

**Files Changed**:
- `web/frontend/src/components/Group_planner/PlaceCard.jsx`

## Issue 3: Backend Configuration - DATABASE_PATH

**Problem**: `config.DATABASE_PATH` might not exist, causing AttributeError

**Fix**: Added defensive check with hasattr
```python
# Before:
if config.DATABASE_PATH.exists():

# After:
if hasattr(config, 'DATABASE_PATH') and config.DATABASE_PATH and config.DATABASE_PATH.exists():
```

**Files Changed**:
- `web/backend/api/app.py`

## CORS Configuration

CORS is already properly configured in `api/app.py`:
```python
CORS(app, 
     resources={r"/api/*": {"origins": config.CORS_ORIGINS}},
     supports_credentials=True,
     allow_headers=["Content-Type", "Authorization"],
     methods=["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"])
```

Default origins: `http://localhost:5173,http://localhost:3000`

If CORS errors persist, check:
1. Backend is running on `http://localhost:5000`
2. Frontend is accessing `http://localhost:5000/api/*`
3. `.env` file has correct `CORS_ORIGINS` if overriding defaults
